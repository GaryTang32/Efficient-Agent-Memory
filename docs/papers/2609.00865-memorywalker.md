## Problem
Production harnesses compress context while the agent runs: Claude Code and Qwen-Agent use a sliding window plus auto-summary, TC-RAG pops entries off a stack, AgentFold folds at more than 3K tokens, MemexRL offloads to a store.

Each compression (eviction) **forks** the conditioning history, so a rollout is a *tree*, not a sequence. Training on it (SFT or RL) can go wrong in two opposite ways:
- **Naive-Compressed** trains on the final compressed stream. Tokens are scored against a prefix that already reflects *later* evictions. The authors call this "time-travel leakage": the context is too short.
- **Naive-Full** trains on the full physical trace. Tokens are scored with evicted content still visible: a train/inference mismatch where the context is too long.

The diagnostic is the train/inference "logdiff". The no-compression floor is 0.014; Naive-Compressed on AgentFold reaches 0.366, about 26× higher.

## Method (training-side only)
- **LogitTree:** replay each of the K+1 branches separately with per-branch loss masks. Exact, but needs K+1 forward/backward passes, which is 5–20× the cost.
- **4D attention mask:** pack all branches into one forward pass with a logical-visibility mask. Exact and a single pass, but needs a custom attention kernel and white-box eviction records.
- **SDCC** (self-distillation for conditioning consistency): train on the compressed walk plus λ·forward-KL(teacher on the reconstructed pre-eviction prefix, stop-gradient ‖ student on the compressed prefix), applied only at diverging leaves.
  - Needs a single backward pass.
  - Works with black-box harnesses (Claude Code, OpenCode); eviction points are detected as prefix divergence between consecutive request payloads.
  - The residual KL ε bounds the behavioural gap by O(√ε) via Pinsker's inequality.

## Results
Setup: Qwen3-4B, GRPO, average exact match over 7 QA benchmarks (NQ, TQA, HotpotQA, 2Wiki, MuSiQue, Bamboogle, FRAMES), live web search.

| Training | TC-RAG | AgentFold | MemexRL | Claude Code | OpenCode |
|---|---|---|---|---|---|
| No compression (Search-R1) | 23.0 (control) | | | | |
| Naive-Full | 34.9 | 27.7 | 32.1 | — | — |
| Naive-Compressed | 36.7 | 33.2 | 28.9 | — | — |
| 4D mask | 37.2 | 34.2 | 33.4 | — | — |
| LogitTree | 40.1 | 37.5 | 45.9 | 35.9 | 35.0 |
| **SDCC** | **46.0** | **42.4** | 43.1 | **37.5** | **36.9** |

- **Untrained Qwen3-4B:** the Claude Code harness scores 26.3 and OpenCode 29.0, against 6–10 for the learnable-editor harnesses. Harness design alone matters a great deal.
- **WideSearch** (Claude Code harness, Qwen3.7-Air, 256 H100s): LogitTree after 15 steps raises Pass@1 from 4.5 to 5.0 and Pass@4 from 7.0 to 10.0.
- **Compression depth:** whichever editor fires removes about 3/5 of the rendered context. AgentFold folds contexts of up to 121K physical tokens into logical views of at most 5.2K.

## Relevance to a Bedrock API-only setup
- **Not implementable for us.** It changes how a model is *trained* (GRPO with custom loss masks, KL terms and attention kernels), and Bedrock-hosted models cannot be trained this way.
- **Lessons we keep:**
  1. Compression is a distribution shift for the model. A model not trained with a given harness may handle edited contexts badly, so every compaction technique we test should be checked for a pass-rate drop, not just token savings.
  2. Prefix divergence between consecutive requests is a practical way to detect evictions in a black-box harness. Our loop's `history_rewrites` counter does exactly this, and it doubles as the count of prompt-cache breaks.
  3. If the user later fine-tunes an open model (e.g. via SageMaker) on compressed trajectories, use SDCC or LogitTree rather than naive replay.
