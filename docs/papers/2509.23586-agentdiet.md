## Problem and evidence
- Average SWE-bench Verified trajectory (Trae Agent + Claude 4 Sonnet):
  - 48.4K tokens over 40 steps.
  - 30.4K of those tokens are tool messages.
  - 13.7K are assistant messages (11.9K of which are tool-call arguments).
  - Because the history is re-sent at every step, that adds up to about **1.0M input tokens per issue**.
- Manual study of 100 trajectories found three kinds of waste:
  - **Useless:** e.g. `ls` output listing `__pycache__`, `make` "Entering/Leaving directory" lines.
  - **Redundant:** `str_replace_editor` arguments repeat code that appears in the result or was viewed earlier.
  - **Expired:** files opened while localising the bug that are no longer relevant.
- KV/prompt caching does **not** remove the need for reduction, and makes reduction harder, because editing any token invalidates the cache for everything after it.

## Key design findings (§2.3)
1. An LLM prompted with the three waste types can find and remove waste. Rules or regexes cannot cover the variety.
2. **Agents cannot reliably do it themselves.** Given an `erase` tool, Claude 4 Sonnet and Gemini 2.5 Pro kept working on the task instead of calling it.
   Reduction therefore runs in a separate **reflection module**, called by the harness, which the agent never sees.
3. **Overhead control:**
   - The reflection module runs on a cheap LLM (GPT-5 mini, roughly 12× cheaper than Claude 4 Sonnet).
   - It sees only a sliding window of the trajectory.
   - It edits only one fixed older step, so cache entries for all earlier steps survive.

## Algorithm (Alg. 1)
After agent step `s` is appended:

1. If `s − a > 0`, serialise step `s − a`. If its length `l_orig ≤ θ`, skip.
2. Build the context from steps `max(0, s−a−b) … s`, wrapped in `<step id="…">` XML.
3. Call `LLM_reflect` to rewrite step `s−a`.
4. If `l_orig − l_reduced > θ`, replace step `s−a` in the trajectory.

Final hyperparameters:

| Parameter | Value | Meaning |
|---|---|---|
| `a` | 2 | delay |
| `b` | 1 | steps of context before the target step |
| `θ` | 500 tokens | skip and benefit threshold |
| `LLM_reflect` | GPT-5 mini | reflection model |
| `s_max` | 50 (SWE-bench Verified), 100 (Multi-SWE-bench Flash) | step limit |

These were chosen by hill-climbing on 100 SWE-bench Verified instances, kept separate from the 200 evaluation instances.

### Prompt
The paper gives an outline:
- job description
- I/O format (`<step id>`)
- the three waste types with examples
- guidelines (replace removed text with a short takeaway; keep XML tags, indentation and line numbers)

The exact text is in the artifact. The copy in AttnCompress's `traj_analyzer.py` (`SYS_PROMPT`) reads:
- "compress the text within the given id … typically shortening it to 20%–50% of the original length"
- "Replace the text to remove to '...' and a short takeaway"
- "keep the original structure unchanged, e.g., XML tags, Python indentation and line numbers"
- worked examples: a huge file (keep the needed part), a verbose passing test ("... (expected output)"), and a `str_replace_editor` argument ("... (see results below)")

That implementation also adds three details not in the paper:
- It **prefills** the assistant turn with `Sure. Here is the compressed content of step {idx}: <step id="{idx}">` and cuts the output at `</step>`.
- It uses temperature 0.7.
- It accepts the rewrite if it saves ≥ 400 tokens or shrinks the step by more than 20%.

## Results

**Choice of reflection LLM** (100 tuning instances; cost normalised to Original = 1.00; Original pass rate 65%)

| `LLM_reflect` | Keep% | Input | Cost (incl. reflection) | Reflection share | Pass% | Steps |
|---|---|---|---|---|---|---|
| Claude 3.5 Haiku | 14.4 | 0.473 | 0.652 | 0.148 | 60 | 42.39 |
| Gemini 2.5 Flash | 21.9 | 0.553 | 0.698 | 0.078 | 63 | 40.95 |
| **GPT-5 mini** | 28.6 | 0.586 | 0.707 | 0.077 | **65** | **38.90** |
| DeepSeek v3 (0324) | 23.7 | 0.606 | 0.733 | 0.052 | 64 | 40.41 |
| Qwen 3 (2507) | 29.0 | 0.722 | 0.818 | 0.065 | 62 | 41.10 |
| LLMLingua-2 (rate 0.25) | 22.5 | 0.603 | 0.753 | ≈0 | 61 | 43.89 |
| Random (drop 75%) | 25.0 | 0.642 | 0.794 | — | 64 | 44.95 |
| Delete all | 0 | 0.428 | 0.655 | — | 58 | 45.43 |

- Even the Random and Delete baselines hold up reasonably well, because `a=2` and `θ=500` only touch long, older steps and the agent re-fetches what it needs. That re-fetching shows up as more steps.
- LLMLingua-2 destroys code and log structure: the paper's figure shows it mangling test names.

**Hyperparameter sweep**
- θ = 0 / 250 / 500 / 1000 / 2000 gives Pass% 62 / 65 / 65 / 60 / 58 and cost 0.669 / 0.700 / 0.707 / 0.765 / 0.816.
- `a = 0` is worst: cost 0.843, Pass 59%, 44.9 steps. Rewriting the newest step immediately removes information the agent is about to use.
- `b > 1` adds cost without benefit.

**Held-out evaluation** (200 SWE-bench Verified + 300 Multi-SWE-bench Flash instances)

| Setting | Input | Total cost | Pass% Orig → AgentDiet |
|---|---|---|---|
| SWE-bench Verified + Claude 4 Sonnet | 0.601 | 0.714 | 64.5 → 66.5 |
| SWE-bench Verified + Gemini 2.5 Pro | 0.591 | 0.623 | 50.5 → 52.0 |
| Multi-SWE-bench Flash + Claude | 0.596 | 0.676 | 40.0 → 39.0 |
| Multi-SWE-bench Flash + Gemini | 0.403 | 0.559 | 21.7 → 22.7 |

- Headline: input tokens −39.9% to −59.7%, total cost −21.1% to −35.9%, Pass% change −1.0 to +2.0.
- **Costs include cached-input pricing** (Table 1 lists cached prices), so the savings already account for prompt caching.
- With Gemini on Multi-SWE-bench Flash, AgentDiet cut instances that hit the step limit from 66 to 26: shorter context gave a more robust agent.

## Limitations
- Only Trae Agent was tested. The experiments cost about $2,000.
- Latency was not measured: the reflection call is on the critical path unless run in parallel, which would mean `a−1`.
- Reflection adds 5–10% overhead.
- Lindenbauer et al.'s observation masking (delay 10) is described as inferior.

## Relevance to a Bedrock API-only setup
- **Training-free, works with any API model.** The agent model and the cheap reflection model are both just API calls. On Bedrock: Claude Sonnet as the agent, with Claude Haiku, Nova or DeepSeek/Qwen as the reflector (the paper shows DeepSeek and Qwen work, at slightly lower Pass%).
- **Cache-aware by design.** Each edit invalidates the cache from step `s−a` onward, i.e. the last `a+1` steps, which are re-written to cache anyway. This is the key property that makes it cheap on Bedrock as well.
- **Bedrock caveats:**
  - Prefilling the assistant turn works for Anthropic models on Bedrock; other Bedrock models may not support it. Fall back to "output only the rewritten step".
  - Use Converse `cachePoint`s so the reflector's own system prompt is cached.

## Implementation plan
1. Get the official prompt and code from the Figshare artifact. Use them verbatim with attribution; the paper is CC BY 4.0, and the artifact's licence is to be checked.
2. Implement it as technique `AgentDiet(a=2, b=1, theta=500, reflect_model=…)`, faithful to Alg. 1, operating on Converse messages. Serialise steps to the same `<step id><think><call><result>` XML.
3. Keep the paper's baselines (Random-75%, Delete, LLMLingua-2) as options for sanity checks.
